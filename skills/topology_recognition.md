# 拓扑视觉识别与融合 Skill

本 Skill 只服务于固定的 `structure`、`links`、`text`、`fusion` 四阶段流程。
前三阶段从各自的一张完整拓扑图片中提取视觉事实、候选值和不确定性；第四阶段只依据结构化冲突上下文输出融合补丁。
它不负责网络计算、平台资源映射、平台 ID 或 Payload 编译。

## 当前阶段优先

- 调用方会在当前任务中明确阶段名称；只执行当前阶段，不补做其他阶段。
- 视觉响应中的 `temporaryModelId` 使用 `tmp_` 前缀且只在当前响应内有效，不得占用程序稳定编号或 Observation、Evidence、unresolved、conflict 命名空间。
- `structure` 使用 `global_structure`，观察设备主体和区域。
- `links` 使用 `global_links`，依据程序标注的 `Nxxx`、`Rxxx` 识别连线。
- `text` 使用 `global_text`，保守读取名称、接口、IPv4、前缀和区域标题。
- `fusion` 不接收图片，只裁决输入中已列出的冲突候选。
- 每次请求只加载本 Skill，不假设网络推理或平台映射 Skill 同时存在。

## 支持的语义设备类型

只在视觉证据支持时使用以下语义类型：

- `switch_l2`：二层交换机；
- `switch_l3`：三层交换机；
- `router`：路由器；
- `public_router`：图片明确表达公共或外部路由角色的路由器；
- `firewall`：防火墙；
- `ids`：入侵检测设备；
- `waf`：Web 应用防火墙；
- `des`：图片明确标注的 DES 设备；
- `client`：终端或客户端；
- `server`：通用服务器；
- `web_server`：图片明确标注的 Web 服务器；
- `database_server`：图片明确标注的数据库服务器；
- `mail_server`：图片明确标注的邮件服务器；
- `monitor_server`：图片明确标注的监控服务器；
- `vpc_server`：图片明确标注的 VPC 服务器；
- `unknown`：图标或文字不足以支持上述具体类型。

不得凭网络常识把 `unknown` 改成具体类型，也不得根据平台的 VM、SW、TSW、`devType`、镜像或 Flavor 反推视觉类型。

## Structure：设备与区域

### 图标、名称与类型分离

- 可见设备主体证明一个节点候选存在，但不必然证明其名称或精确类型。
- 节点名称来自靠近设备主体且排版关系明确的文字；区域标题、接口名和 IPv4 不是节点名。
- 类型候选来自图标形状、图标内标记和明确类型文字的组合。
- 厂商或型号只有在图片直接可见且 Schema 支持时记录。
- 名称模糊时保留可见原文和有限合理候选；同一文字不得复制成多个确定名称。
- 图标与名称证据冲突时分别保留并降低置信度或创建未解析项。

### 节点几何

- `bbox` 包围设备图标或主体，不包含大范围连线和无关文字。
- `center` 以设备主体 `bbox` 的几何中心为主，并位于该框内。
- 多个紧邻图标只有在主体清晰分离时才分别输出。
- 普通说明文字、接口名、IPv4、网段、协议、区域标题、水印和装饰元素不是节点。
- 图例中的示范图标只有在明确属于拓扑画布时才作为设备候选。

### 区域

- 区域由边框、背景色、分组容器或明确标题支持。
- 区域 `bbox` 覆盖边界，区域本身不作为节点或链路端点。
- 区域名称保留原文和候选；`fillColor` 仅在可辨认且 Schema 支持时记录。
- 成员候选主要依据设备主体中心与区域边界的关系；跨越边界时保留多个候选或未解析状态。

## Links：连线与端点

- 只有实际可见的连接线、箭头或连接符才能支持链路候选。
- `polyline` 按可见路径记录端点和必要折点，连续多段折线属于同一链路时不拆分。
- 端点优先引用调用方提供的 `Nxxx`；不得引用不存在的编号。
- 端点在多个设备之间时保留所有合理 `sourceNodeCandidates` 或 `targetNodeCandidates`。
- 接口端点不清楚时保留候选，不虚构接口名。
- 一对多扇出只有在主线与各分支连续可见时才输出相应链路。
- 两条线只是几何相交时不自动建立连接；实心点、汇聚符号或清晰接头可作为连接证据。
- 没有连接标记且线条可连续穿越时设置 `crossingUncertain` 或创建未解析项。
- 区域边界、表格线、图标轮廓、文字下划线和装饰线不是链路。
- 链路方向不代表网络流向，只表达两个视觉端点。
- 发现未编号设备主体时，将其作为 `additionalNodeCandidates` 保留几何、类型候选和 Evidence；不自行分配稳定节点编号。

## Text：名称、接口与 IPv4

- 所有可见文字先保留 `rawText`，再表达解析候选，不能只保留模型修正后的字符串。
- 节点名、接口名、IPv4、前缀和区域标题分别记录，不把相邻但不同语义的文字合并成一个确定值。
- 接口名按图片原文记录，不按厂商命名习惯补齐。
- IPv4 按图片原文记录，并只列出视觉上有依据的合法读数候选。
- 带前缀 IPv4 与裸 IPv4 必须区分；裸 IPv4 不默认添加 `/24` 或其他前缀。
- `labelBBox` 只覆盖名称或接口文字；`ipBBox` 只覆盖 IPv4 或前缀文字。
- 接口名与 IPv4 位于同一文本块时，仍分别保存其原文和候选。
- 文字与节点、接口或链路的归属依赖空间排版；存在多个合理对象时保留多个稳定 ID 候选。
- 字符 `0/O`、`1/l/I`、`5/S` 等无法确认时保留有限候选并降低置信度。
- 不把速率、VLAN、描述或网段标题误作 IPv4。
- 不生成图片不可见的接口、备用地址或前缀。
- 文字阶段必须紧凑输出：同一文字块只输出一次，`rawText` 保留可见原文但不超过 240 个字符，每个名称/IP/归属字段最多保留 4 个去重候选，Evidence 使用短描述。

## Evidence

- `VISUAL_ICON` 支撑设备主体和图标类别。
- `VISUAL_TEXT` 支撑名称、接口、IPv4、区域标题和其他可见文字。
- `VISUAL_LINE` 支撑链路路径、端点和交叉状态。
- `VISUAL_REGION` 支撑区域边框、背景和范围。
- `MODEL_INFERENCE` 仅用于非直接文字的模型判断，例如由图标形状提出类型候选。
- 不把模型推断标记为 `VISUAL_TEXT`，不使用 `NETWORK_DERIVATION` 伪造视觉证据。
- Evidence 的真实来源只能是 `global_structure`、`global_links` 或 `global_text`；调用方负责登记，模型仅在目标 Schema 包含 `sourceViewId` 时输出该字段。
- Evidence `bbox` 应紧凑覆盖相关内容且宽高都大于 0；竖直线或水平线必须把可见线宽包入正面积框，不能输出退化框。`description` 说明看到了什么，不声称程序已验证。
- 融合阶段不得创建、删除或修改 Evidence。

## 置信度与不确定性

- `0.90–1.00`：文字、图标、线条或区域证据清楚且一致。
- `0.75–0.89`：主要事实可靠，但字符、边界或端点存在轻微歧义。
- `0.50–0.74`：至少存在两个合理候选或明显遮挡。
- `<0.50`：不应作为唯一确定事实采用，应保留候选或未解析项。
- 类型、名称、端点、文字归属、接口归属、IPv4 归属或区域归属无法确认时，保留全部有限合理候选。
- 不用单一置信度掩盖冲突，也不删除 Evidence 或候选来制造确定性。

## Fusion：结构化语义裁决

Fusion 正在融合三个已经完成的视觉观察阶段，不是在重新识别图片。

- 只处理输入中的 `conflictId`，只选择该冲突列出的 `candidateIndex`。
- 可以判断重复节点、节点类型、名称、文字归属、接口归属、IPv4 归属、链路端点、交叉状态和区域成员候选。
- 允许的 action 仅为 `SELECT_CANDIDATE`、`KEEP_MULTIPLE_CANDIDATES`、`MERGE_OBJECTS`、`KEEP_OBJECTS_SEPARATE`、`BIND_REFERENCE`、`LEAVE_UNRESOLVED`。
- 证据充分时可选择已有候选；证据不足时必须保留多个候选或未解析状态。
- 不创建输入中不存在的节点、接口、链路、区域、候选、Evidence 或引用。
- 不修改稳定对象 ID、`bbox`、`center`、`polyline`、Evidence ID 或 `sourceViewId`。
- 不删除原始候选，不重新统计 summary，不直接输出最终 `TopologyObservation`。
- 不计算 CIDR、默认网关、广播域、路由或平台字段。
- `reasonCode` 使用简短大写下划线代码，不输出长篇解释。
- 输入没有冲突时返回空 `decisions`，不得制造冲突或新事实。

## 明确边界

- 程序负责稳定编号、坐标映射、确定性去重、Evidence 与未解析项 ID、融合补丁校验、最终 Observation 和 summary。
- M5 负责接口最终规范化、CIDR、网关、广播域、重复 IP 和其他网络推理。
- 后续平台模块负责平台类型、资源查询、内部 ID、Payload 编译、验证和提交。
- 不硬编码任何样例的文件名、哈希、节点、IPv4、区域或预期数量。

最终响应只表达当前阶段目标 Schema 允许的视觉观察或融合补丁。
