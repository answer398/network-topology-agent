# 初次结构化提取流程

本流程用于依据当前任务、当前一个 Skill、当前图片视图和目标 JSON Schema 产生一次结构化结果。
在内部依次观察和自审，最终只返回 JSON 对象，不返回过程说明。

## 读取输入

1. 阅读当前任务，识别任务明确给出的 `taskId`、图片元信息和允许使用的上下文。
2. 阅读所有视图的 `viewId`、宽度和高度。
3. 阅读目标 JSON Schema 的字段、枚举、必填项和嵌套关系。
4. 只应用本次请求加载的一个 Skill，不假设其他 Skill 已加载。
5. 将每张图片视图独立观察，但用 `sourceViewIds` 保留来源。
6. 不从 `viewId`、文件名或任务标识推导拓扑答案。

## 全局观察顺序

1. 先观察画面整体布局、可能的区域、设备图标群和主干连线。
2. 再观察每个可能设备主体、邻近名称、接口标签和 IP 文字。
3. 再沿可见线条追踪端点、折点、重叠和交叉。
4. 最后检查区域标题、区域边界和设备中心是否位于区域内。
5. 在局部信息与全局结构冲突时保留歧义，不用常识强行统一。

## 区域提取

- 区域通常由闭合或近似闭合的边框、填充色或区域标题表达。
- 为可见区域记录名称原文、名称候选、边界框、颜色候选和置信度。
- 区域框不是链路。
- 区域不是节点。
- 区域标题不是节点名称，除非另有清晰设备主体和对应几何关系。
- 根据设备主体中心提出区域成员候选，不根据跨区域文字中心判断。
- 边界不清楚时保留候选或未解析项。

## 节点提取

- 只有具有设备主体视觉证据的对象才能成为节点候选。
- 分离识别设备图标、节点名称和语义设备类型。
- 普通文字不是节点。
- IP 文字不是节点。
- 接口标签不是节点。
- 区域标题和区域框不是节点。
- 仅有文字而没有设备主体时，将其作为未绑定文字证据，不虚构节点。
- 为每个节点记录设备主体 `bbox` 和由其计算或观察得到的 `center`。
- 名称保留图片原文；模糊字符进入 `nameCandidates`。
- 类型不明确时使用类型候选、较低置信度或 `unknown`。
- 不用名称中的常见词覆盖明显不同的设备图标证据。
- 不因多个视图重复看到同一对象而在此阶段去重；保留各自观察和来源。

## 接口与 IP 提取

- 接口名和 IP 是节点附近的文字观察，不是独立节点。
- 分别记录接口名原文、候选、文字框和置信度。
- 分别记录 IP 原文、IP/前缀候选、文字框和置信度。
- 不根据常见接口命名规则补齐图片不可见的接口。
- 不根据同网段常识补齐图片不可见的 IP。
- 不把裸 IP 自动补成任意前缀。
- IP 与接口或节点归属不清楚时保留候选关系。
- 一个文字框可能同时邻近多个对象时，不随机绑定。
- 文字只部分可见时保留原始可见部分和候选，不静默纠正。

## 链路提取

- 链路必须由可见线条或明确连接符提供视觉证据。
- 沿整条路径追踪端点和折点，将连续多段折线记录为同一链路候选。
- 线条交叉不自动表示连接。
- 交叉处没有连接点或汇聚符号时，设置交叉不确定性或未解析项。
- 区域边框、表格线、装饰线和文字下划线不是链路。
- 链路端点必须接近设备主体边缘或明确接口位置。
- 端点在两个设备之间无法区分时保留多个候选。
- 不用网络合理性凭空移动端点。
- 不为看不见的冗余链路、隧道或逻辑连接创建对象。

## Evidence

- 为支撑视觉事实的文字、图标、线条和区域创建 Evidence。
- Evidence 的 `evidenceId` 必须使用 `evidence_` 前缀，例如 `evidence_001`。
- 所有对象的 `evidenceIds` 必须逐字符引用同一输出中已存在的 `evidenceId`。
- 可见文字使用 `VISUAL_TEXT`。
- 设备图标使用 `VISUAL_ICON`。
- 线条和端点使用 `VISUAL_LINE`。
- 区域边框、填充或标题使用 `VISUAL_REGION`。
- 非直接视觉文字的语义判断使用 `MODEL_INFERENCE`。
- 不把程序未来计算的 CIDR、网关或去重结论标记为视觉证据。
- Evidence 的 `sourceViewId` 指向实际提供的视图。
- Evidence 的 `bbox` 只覆盖相关可见内容，不覆盖无关大区域。
- 对象的 `evidenceIds` 只引用本次输出中实际存在的 Evidence。

## 来源与坐标

- 每个节点的 `sourceViewIds` 列出实际观察到它的视图。
- 不列出本次未提供的视图。
- 坐标使用当前视图像素坐标，原点为左上角。
- `bbox` 必须有正宽度和正高度。
- `center` 应位于对应设备主体边界框内。
- 不在此阶段把视图坐标转换为平台坐标。
- 多视图坐标合并和还原由后续程序处理。

## 不确定性

- `0.90` 到 `1.00` 只用于视觉证据明确的观察。
- `0.75` 到 `0.89` 表示较可靠但仍可能有细节误差。
- `0.50` 到 `0.74` 表示存在明显歧义。
- 低于 `0.50` 的值不应伪装成可自动采用的事实。
- 对模糊文字保留多个合理候选及各自依据。
- 对模糊图标保留语义类型候选，必要时使用 `unknown`。
- 对阻塞性 IP、前缀或端点歧义创建 `unresolvedItems`。
- unresolved 对象的 `tempId` 必须使用 `unresolved_` 前缀。
- 不通过删除不确定性来制造看似完整的结果。

## 禁止越界推断

- 不根据防火墙图标生成 NAT、防火墙策略或端口映射。
- 不生成 OSPF、静态路由、动态路由配置或隧道。
- 不生成图片不可见的描述、管理账号、VLAN 或运维属性。
- 不计算最终广播域、CIDR 或网关。
- 不执行节点、接口、链路或区域去重。
- 不生成内部 ID、平台 ID、镜像、Flavor 或平台 Payload。
- 不根据固定样例、文件名、哈希或预期数量补齐对象。

## 输出前内嵌自审

在内部完成以下检查，但不要输出审计说明：

1. 检查每个节点是否有设备主体，而不是普通文字、IP、接口标签或区域。
2. 检查每条链路是否有可见线条，并排除区域框和装饰线。
3. 检查交叉线是否被错误当作连接。
4. 检查多段折线是否被错误拆成多条链路。
5. 检查端点是否接近设备主体或明确接口。
6. 检查区域是否只出现在区域集合，不出现在节点或链路集合。
7. 检查 Evidence、`evidenceIds` 和 `sourceViewIds` 是否一致。
8. 检查所有受 Schema pattern 约束的 ID 前缀和引用逐字符一致。
9. 检查坐标、置信度、枚举和字段类型是否符合 Schema。
10. 检查所有必需集合均为数组。
11. 检查没有平台 ID、资源 ID 或图片不可见配置。
12. 若没有观察到对象，使用显式空数组，不虚构占位对象。
13. 自审完成后只输出一个符合 Schema 的 JSON 对象。
